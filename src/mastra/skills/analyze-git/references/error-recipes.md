# Error recipes — things that go wrong with `git log` parsing

Every entry below has bitten us in production. The script handles all of them; **do not** reimplement parsing in the agent.

---

## 1. Shortstat appears on `idx+2`, not `idx+1`

**Symptom:** every commit's `added`, `deleted`, and `files_changed` are zero.

**Cause:** `git log --format=… --shortstat` emits the format line, then a blank line, then the shortstat.

```
+++abc123|2026-05-21 …|mohdmusthafaneo|fix: foo+++
                                                       ← blank line
 3 files changed, 142 insertions(+), 8 deletions(-)    ← idx+2
```

**Fix:** scan ahead to `idx+1`, `idx+2`, `idx+3` and break on the first line containing `changed`.

---

## 2. Root commit returns empty `git diff-tree`

**Symptom:** the very first commit has 0 files / 0 lines.

**Cause:** the root commit has no parent, so `git diff-tree -r <root>` lists nothing.

**Fix:** use `git log --numstat` instead, which walks every commit including the root.

---

## 3. Binary files appear as `-` `-`

**Symptom:** `numstat` row `-\t-\tpath/to/image.png`.

**Fix:** filter rows where either column is `-`.

---

## 4. Author names match numstat regexes

**Symptom:** author `mohd123` ends up bucketed as a file count of 123.

**Fix:** require the row to be tab-separated AND contain a `/` in the path column.

---

## 5. `splitlines()` discards trailing blanks

**Symptom:** `len(lines)` is one less than you expect, and your `idx+1` references are off by one.

**Fix:** always iterate raw lines by explicit index, never trust contiguous indices after `splitlines()`.

---

## 6. Lockfile and generated-code inflation

**Symptom:** `package-lock.json` shows up as 19,730 lines; `src/generated/prisma/**` adds ~85k LOC. Both inflate "productivity" misleadingly.

**Fix:** the script computes **two** LOC totals:
- `lines_added_raw` / `lines_deleted_raw` — everything, including noise.
- `lines_added_product` / `lines_deleted_product` — excluding lockfiles and `src/generated/**`.

Use `*_product` for any narrative that claims "code shipped."

---

## 7. `main` is stale

**Symptom:** every report says "main is behind by N commits" and N is in the hundreds.

**Fix:** always emit `branching_and_delivery.dev_ahead_of_main_commits`. If it's >50, flag it as a release risk.

---

## 8. Subject contains `|`

**Symptom:** `split("|", 4)` overflows and `subject` becomes empty.

**Fix:** use a unique sentinel (`+++ANALYZE_GIT+++`) at both ends, then `rsplit` on the closing sentinel.

---

## 9. Conventional-commit scope vs free-form

**Symptom:** `feat(mastra): …` is classified as `feat` (commit type) but you wanted to count it under `ai-agents` (area).

**Fix:** the script runs two classifiers:
- `classify_commit_type()` → `feat`, `fix`, etc. (for commit-type breakdown).
- `classify_area()` → `scope:mastra` or `ai-agents` (for productivity-by-area).

These are independent. Don't merge them.

---

## 10. `main` doesn't exist

**Symptom:** `git rev-list main..dev` fails with `unknown revision`.

**Fix:** the script catches `RuntimeError` and emits `dev_ahead_of_main_commits: 0`. Don't crash.

---

## 11. Bash quoting fights you

**Symptom:** trying to pipe `git log` to awk with embedded `+++` in the format string fails on zsh, fish, or even bash with weird locales.

**Fix:** all parsing lives in Python. The shell only invokes `git`. Don't try to be clever.

---

## 12. Generated dirs hide real work

**Symptom:** `src/generated/prisma/models/Organization.ts` is 10,375 lines, but it's auto-generated by `prisma generate`. Counting it as "developer productivity" is wrong.

**Fix:** the script's `is_noisy_path()` matcher excludes anything matching `src/generated/`. Edit `NOISY_PATH_PATTERNS` to add your project's generated dirs (e.g., `src/api/generated/`, `proto_gen/`).

---

## 13. Time-zone confusion

**Symptom:** `git log --format=%ai` returns the commit timestamp in the **author's** local timezone, not yours.

**Fix:** the script uses `%ai` (author date, ISO) and reports hour-of-day under the label "IST." If your team is multi-region, switch the label — don't try to normalize across timezones. Just call it out in the narrative.

---

## 14. `--since` vs explicit date range

**Symptom:** the user says "last 30 days" but the script sees commits from 90 days ago because they're on a feature branch.

**Fix:** `--since` filters at git's level, but only on the commits that **reach** `HEAD` after following first-parent. For accurate time-windowing, use `--since="30 days ago"`. For exact dates, use `--since="2026-01-01"`.

---

## 15. Empty branch

**Symptom:** `git log <branch>` returns nothing.

**Fix:** the script raises `RuntimeError("No commits found")` rather than producing an empty report. Catch this in the agent and report "no data" to the user.

---

## 16. "can't open file ... analyze_git.py"

**Symptom:** sandbox command fails with `No such file or directory` when running the analyzer.

**Cause:** the script was never materialized into the workspace filesystem. Paths under `scripts/` are skill-root-relative for `skill_read`, not sandbox-cwd-relative.

**Fix:**

1. `skill_read` → `scripts/analyze_git.py` (full file).
2. `mastra_workspace_write_file` → `tools/analyze_git.py` with that exact content.
3. `python3 tools/analyze_git.py --repo <clone> --branch <branch> ...`

---

## 17. `mastra_workspace_write_file` validation failed / empty args

**Symptom:** tool error `path: expected string, received undefined` (or empty `{}` args).

**Cause:** the model called write without both `path` and `content`, or tried to pass a truncated script.

**Fix:** always pass `path` (string) and `content` (full string from `skill_read`). Do not summarize the Python source.

---

## TL;DR for the agent

If any number in the JSON looks wrong, the bug is in the script. Open `scripts/analyze_git.py` via `skill_read`, find the rule above that matches, and fix the script — don't re-parse `git log` in the agent. If the script won't run, follow recipe 16.
